# 지도 클릭 기반 신규 정류장 위치 설정

> 현재 버전은 노선별 복정역 하차 지점을 사용합니다. 공통 지점 관련 아래 최초 설명은 과거 기록이며, 최신 사용법과 v2 이관 결과는 [하차 지점 분리 보고서](r03_r04_split_dropoffs_20261115.md)를 확인하세요.

## 사용 방법

1. `노선 및 운영 관리 → 신규 정류장 위치 설정`을 연다.
2. R03/R04 노선과 승차 정류장 또는 공통 `BOKJEONG` 복정역 하차 지점을 선택한다.
3. 지도에서 도로변 후보를 클릭한다. 빨간 임시 마커와 선택 위도·경도를 확인한다.
4. `후보 좌표 저장`을 누른다. 저장 후 해당 위치의 마커와 좌표 표를 확인한다.
5. 수정할 때 같은 정류장을 선택해 다시 클릭·저장한다.
6. 승차 후보 2개와 복정역 하차 후보를 모두 저장한 뒤 `선택 노선 OSRM 도로 경로 조회`를 누른다.

복정역은 R03/R04가 공유하는 하차 후보다. 사용자 저장 전에는 기존 GIS 역 기준점만 참고용으로 보여 주며, OSRM 입력으로는 사용하지 않는다. 실제 하차 후보를 명시적으로 저장해야 경로를 조회할 수 있다.

## 재사용 및 저장 구조

- 기존 `independent_route_views.py`의 `st_folium(..., returned_objects=['last_clicked'])` → `lat/lng` 수집 패턴을 재사용했다. 지도 배경도 기존 `background_map`을 사용한다.
- 기존 R02 연구 등록부 저장 기능은 R03/R04 용도로 사용하지 않았다. R01/R02 CSV와 운영 SQLite에는 쓰지 않는다.
- 저장 파일: `data/derived/new_route_settings/locations.json`.
- 이전 버전 백업: 같은 폴더의 `backups/locations.<고유값>.json`.
- 설정은 버전·revision·정류장 좌표·수정 시각·출처·노선별 OSRM 도로 모형을 포함한다. 좌표 출처는 `사용자 지정 후보 좌표`다.
- 각 수정에서 기존 파일 형식을 검증하고, 원본 바이트를 백업하고, 백업을 다시 읽어 동일성을 검사한다. 임시 파일에 새 JSON을 기록·fsync한 후 `os.replace`로 교체한다.
- revision 비교와 배타적 잠금 파일로 동시 저장을 거절한다. 수정 중 원본 파일이 달라져도 교체하지 않는다.
- 저장 실패 시 원본을 보존하고 오류를 화면에 표시한다. 손상된 JSON은 자동 초기화하거나 덮어쓰지 않는다.
- 프로세스 강제 종료 후 `.lock`이 남으면 이후 저장은 중단된다. 관리자는 다른 저장 프로세스가 없는지 확인하고 잠금·백업을 점검해야 한다. 자동으로 잠금을 강제 해제하지 않는다.
- 후보 설정과 백업 폴더는 `.gitignore`에 추가했다. 실행 중 생성되는 좌표 설정을 Git에 포함하지 않는다.

## 좌표·경로 검증 상태

좌표 입력은 유한한 숫자이며 위례 주변 범위(위도 37.40~37.55, 경도 127.05~127.22)여야 한다. 위경도 뒤바뀜, NaN/무한대, 누락 및 범위 밖 클릭은 저장하지 않는다. 이는 편집 범위 검사이며 차량 접근성을 검증하는 기능이 아니다.

OSRM 조회는 기존 `route_engine.calculate_road_route`를 사용한다. 클릭 후보 좌표가 공개 OSRM 서비스로 전송됨을 버튼 위에서 안내한다. 기존 OSRM 원본 캐시는 수정하지 않는다. 저장된 후보 3개를 S01 → S02 → 복정역 순서로 조회하고, OSRM driving 출처, 유효한 도로 모형, 거리·시간, 경로에 투영한 정류장 순서와 접근 거리(기존 100m 기준)를 검사한다. 형상 검사를 통과한 결과만 별도 설정에 저장한다.

검사된 OSRM 도로 모형은 위치 설정 지도·통합 지도·대시보드에서 표시하고 거리·시간은 모형 값으로 구분한다. 통신 실패, 경로 없음, 형상·방문 순서 불일치 시 검증 필요 상태를 표시하며 과거 성공 결과도 해제한다. 좌표 수정 시 해당 노선 경로를 무효화하고, 복정역 수정 시 두 노선 경로를 모두 무효화한다. 재로드 시 경로 서명도 현재 좌표와 비교한다.

OSRM 모형 확인은 차량 진입·정차·보행 접근·고속도로 진입 회피·회차 가능성 확인이 아니다. 별도 현장·통행 규제 검증이 필요하다. 신규 노선의 `road_model_complete`와 실제 배차에서 요구하는 `road_complete`를 분리했고 후자는 계속 false로 유지한다. 이번 기능만으로 신규 운행편 등록·배차 확정·정시성 계산이 활성화되지 않는다. 위례터널 경유도 강제하지 않는다.

## 후속 오류 수정: 정류장 조회 함수 인자 계약

보고된 오류: `boarding_stops() takes 0 positional arguments but 1 was given`.

호출 경로는 `app.py → show_new_stop_settings()`이며, 위치 설정 화면은 `boarding_stops(data)`와 `destination_stop(data)`를 호출하고 있었다. 전달한 값은 노선 ID가 아니라 설정 딕셔너리다. 점검 시 디스크에는 선택적 settings 인자를 받는 정의가 있었으므로 새 프로세스에서는 원래 오류가 재현되지 않았다. 실행 중 이전 무인자 함수 참조가 남은 경우가 가능한 원인이지만, 실제 실행 중 프로세스의 함수 참조까지 확인한 것은 아니다.

공개 조회 API를 기존 `boarding_stops()`와 `destination_stop()` 무인자 계약으로 통일했다. 하나의 설정 스냅샷이 필요한 `plans()` 내부 처리는 별도 `_boarding_stops(settings)`, `_destination_stop(settings)` 함수로 분리했다. 프로젝트의 모든 공개 조회 호출부를 확인하고 위치 설정 화면에서도 인자를 전달하지 않도록 수정했다. `new_stop_settings.py`의 저장·백업·무결성 로직은 변경하지 않았다.

이번 변경 파일: `new_routes.py`, `new_stop_views.py`, `test_new_stop_settings.py` 및 이 보고서.

추가 회귀 검증:

- `sewook31` 및 `drt_system`의 운영 Python 코드에서 두 공개 조회 함수에 인자가 전달되는 호출이 없는지 AST 검사.
- 엄격한 무인자 함수로 이전 계약을 모사한 실제 app.py AppTest.
- R03/R04 각각 후보 정류장 2개와 공통 복정역 선택 목록 확인.
- 각 대상 클릭 좌표 추출, 임시 마커 확인, 저장, 기존 좌표 수정, 새 AppTest 세션에서 저장 좌표 재조회.
- 별도 Python 프로세스로 설정을 읽어 영구 저장 확인.

실행 중 화면이 이전 함수 참조를 계속 사용하면 Streamlit 서버를 한 번 종료 후 동일 프로젝트의 `sewook31/app.py`로 재시작해야 한다. 브라우저 시각 조작은 이번 수정에서도 수행하지 않았다.
