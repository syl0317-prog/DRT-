# 고정 순차 경유 노선·합승 배차 구현

기존 브랜치 `fix/integrated-drt-operations`와 미커밋 작업을 보존했다. 이번 작업은 예약·지도·고정 운행편 배차만 변경했다. 정시성 분석 코드·데이터·화면은 변경하거나 실행하지 않았다. 기존 5개 주요 메뉴와 시뮬레이션 알고리즘은 유지했다.

## 운영 노선과 지도

| 노선 | 고정 방문 순서 | 근거 | 현재 표시 |
|---|---|---|---|
| R01 | D01 → D02 → D03 → D04 → T01 위례별역 | drt_system/data/osrm_cache.json의 정확히 같은 방향·경유 순서 키 | 파랑 #2563EB, 하나의 순차 경유 도로 선 |
| R02 | V05 → V06 → V07 → V08 → T02 위례역사공원역 | 기존 등록부 stop_order와 저장된 방향별 3구간 | 주황 #F97316, 연결된 저장 도로 선 + 마지막 미검증 점선 |

R01의 기존 정류장별 직행 4개 선을 제거하고 전체 경유 OSRM 캐시를 읽기 전용으로 사용한다. 해당 캐시는 84개 좌표, 모형 거리 1.76km, 모형 이동시간 약 4.993분이며 조회 시각은 2026-11-11T07:13:15.453128+00:00이다. 이것은 실측 운행시간이나 현재 교통정보가 아니다.

좌표 범위, 방향 순서에 따른 경로상 위치 증가, 정류장과 도로 형상 사이 100m 이내 스냅을 검사한다. R01 정류장별 경로 이격은 약 16.54m, 15.60m, 1.42m, 15.72m, 69.24m다. 이 차이를 도로 주행으로 간주하지 않고 가는 점선 접근 표시로 구분한다. 운행편 등록 시 실제 접근·정차·고정 경로 운행 확인 근거를 별도로 요구한다.

R02 V08→T02는 확정하지 않았다. 미확인 구간이나 잘못된 좌표·방문 순서·실험용 도로 자료를 실제 도로 실선으로 대체하지 않는다. 마지막 구간이 없으면 전체 거리·시간 산출과 실제 운행편 등록을 막는다. 시험용 형상은 테스트 운행편에만 허용한다.

대시보드, 예약 옆 지도, 통합 노선 지도, R02 관리 지도, 기존 경유지 지도, 관제 모형의 운영 노선 배경은 동일한 공통 렌더러를 사용한다. 가상정류장은 1~4 번호, 최종 트램은 5번 및 열차 아이콘으로 표시한다. 기존 경유지 연구 미리보기는 회색 별도 레이어로 유지하고 기본 숨김 처리했다. 관제의 모형 차량 이동·지연 상태 색상은 별도 의미이며 알고리즘을 변경하지 않았다.

## 예약에서 합승 배차까지

1. 승차 정류장으로 노선·최종 목적지를 자동 결정한다. 예약으로 고정 방문 순서를 바꾸지 않는다.
2. 기존 요청처럼 희망 승차 시각으로 검토 접수하거나, 명시적으로 등록한 차량·날짜별 운행편을 선택한다.
3. 운행편을 선택하면 해당 정류장의 등록된 예정 승차 시각을 적용한다. 서로 다른 정류장의 승객도 같은 run_id와 차량에 합승한다.
4. 등록 차량·정원, 출발 시각, 전체 도로 모형, 정류장 접근 확인 근거, 순서별 예정 분을 확인한다. 실제 차량이나 운행편을 기본값으로 생성하지 않는다.
5. 하나의 SQLite IMMEDIATE 트랜잭션 안에서 같은 운행편의 활성 예약 인원을 합산하고 정원을 검사한다. 다른 운행편·기존 배정과 동일 차량 시간이 겹치면 차단한다. 날짜 미확인 CSV 차량을 가용 차량으로 가정하지 않는다.
6. 취소 예약은 합계에서 제외하며 좌석을 다시 사용할 수 있다. 대기 요청은 같은 운행편으로 재검토할 수 있다.
7. 대기 요청의 승차 시각이 운행편과 다르면 자동 변경하지 않는다. 운영자가 화면에서 시간 변경에 동의한 경우에만 변경하고 원래 희망 시각을 보존한다.
8. 노선 좌표·순서·도로 시간 근거가 운행편 등록 당시와 달라지면 새 배정을 막는다. 이미 저장된 예약을 자동 수정하지 않는다.

차량과 운행편은 통합 예약 SQLite의 별도 fixed_vehicles/fixed_runs 테이블에 명시적 등록 버튼으로 저장한다. 실제 운영 DB·CSV는 이번 개발·검증 중 변경하지 않았다. 기존 R02 연구용 차량이나 차량 수 슬라이더를 실제 차량으로 가져오지 않는다. 시험용 차량·운행편은 test_only로 구분하며 배정 결과에 실제 운행이 아니라고 표시한다.

시간표에는 첫 승차지 0분부터 최종 트램까지 5개 예정 분이 필요하다. 역순·NaN·도로 모형보다 짧은 시간을 거절한다. 정차·접근·회차·공차 이동 여유는 실제 운영 자료로 운영자가 확보해야 한다. 물리적 차량 위치·운행 개시를 자동 확인하는 기능은 없다.

## 화면

- 예약 및 배차 관리: 전체 노선 지도, 고정 경유 순서, 정류장별 배정·대기 승객, 최종 하차 예정 인원, 차량·운행편별 정원·탑승 예정 인원·배정/대기 건수.
- 노선 및 운영 관리: 기존 메뉴 안에 차량·운행편 등록 하위 화면 추가. 주요 메뉴 수는 5개 유지.
- 원본 R02 등록부의 3구간 거리·시간은 전체 T02 경로와 혼동하지 않도록 원본 저장 구간이라는 표기를 추가.
- 날짜 없는 과거 예약은 날짜별 운행편 합계에 섞지 않는다. 실제 운행 상태는 데이터 없음으로 표시.
