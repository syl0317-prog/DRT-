# 통합 지도 및 예약 기능 최종 점검

## 수정 결과

R04의 S01→S02 시각화 직선과 S02 이후 도로만 표시하던 구성을 제거했다. R01/R02/R03과 같은 공통 렌더러를 사용하며 R04도 저장된 전체 OSRM 형상(S01→S02→R04-BOKJEONG)을 초록색으로 표시한다. 관련 범례·tooltip·화면 안내 문구를 제거했다.

좌표, 하차 지점, 저장 OSRM 형상 및 거리·시간은 변경하지 않았다. R03의 목적지는 R03-BOKJEONG, R04는 R04-BOKJEONG이다. 실제 저장 데이터에서도 양쪽 OSRM 모형이 유효하고 전체 형상을 표시함을 확인했다.

방향·좌표 서명·경유 순서가 맞지 않거나 도로 데이터가 누락되면 경로를 그리지 않고 `경로 확인 필요`로 안내한다. 형식이 손상된 도로 기록도 지도 읽기에서 해당 기록만 제외하며, 정상 노선과 후보 마커를 유지한다. 이 읽기용 처리로 파일을 초기화하거나 손상 기록을 덮어쓰지 않는다. 저장 시 엄격한 데이터 무결성 검증은 유지한다. 설정 자체나 정류장 좌표 형식이 손상된 경우에는 계속 오류를 표시하며 백업 확인이 필요하다.

## 예약·배차 지원 범위

R01~R04가 동일한 예약 화면을 사용한다: 노선 선택 → 승차 정류장 선택 → 노선별 목적지 자동 지정 → 날짜·시간·인원 입력 → 예약 접수 → 목록 확인 → 취소.

신규 노선에서도 S01/S02 각각 복수 인원을 접수하고 정류장별 대기 인원을 집계한다. S02 예약을 먼저 접수해도 저장되는 방문 순서는 S01→S02→노선별 복정역이며, 예약 생성 순서로 노선 순서를 바꾸지 않는다. 접수·취소 결과는 대시보드와 정류장별 대기 집계에 반영한다.

다만 R03/R04의 실제 차량 접근·정차·회차 및 운영 조건은 미검증이다. **예약 접수·대기와 순차 방문 계획·대기 인원 집계를 지원하며, 실제 승차 운행 및 배차 확정을 검증한 것은 아니다.** 신규 접수는 `배차 검토 필요`, 차량은 미배정, 시뮬레이션은 제외 상태를 유지한다. OSRM 모형과 시험 차량이 있어도 신규 노선 운행편을 등록할 수 없다. 임의 차량, 위치, 도착 시각, 정시성 수치를 생성하지 않는다.

기존 연구·시험 운행편은 별도 분류를 유지한다. 이번 작업에서 R03/R04 모의 배차 기능을 새로 만들거나 실제 배차 제한을 완화하지 않았다. 다른 팀원의 정시성 계산 및 기존 R01/R02 예약·배차 엔진은 수정하지 않았다. 신규 노선의 예약 화면 배차 제한 안내만 실제 미검증 조건에 맞게 정리했다.
