# 운영 UI 정리 및 예약 데이터 일관성 검증

기존 `fix/integrated-drt-operations` 브랜치와 미커밋 변경을 보존했다. 주요 메뉴는 5개로 유지했다. 예약 생성·합승·취소의 저장 규칙과 고정 노선 경로는 유지했으며, 이번에는 읽기 전용 검증과 표시·배치 위주로 개선했다.

## 원본 예약 조사 결과

모든 SQLite 조회는 URI `mode=ro` 연결로 수행했다. 자동 보정·삭제·병합·상태 갱신을 하지 않았다.

| 자료 | 읽기 전용 확인 결과 | 메인 운영 집계 |
|---|---|---|
| sewook31/data/reservations.csv | 5건, 현재 규칙 기준 R01→T02 2건 | 과거 CSV로 구분. 신규 운영 집계 제외 |
| data/derived/unified_reservations/reservations.sqlite3 | requests 0건 | 현재 신규 접수 없음 |
| data/derived/drt_routes/routes.sqlite3 | registry bookings 0건 | 현재 등록부 예약 없음 |
| drt_system/data/reservations.csv | 별도 과거 사본 6건, 현재 규칙 기준 R01→T02 3건 | 현재 메인 앱 연결 자료 아님. 자동 병합하지 않음 |

과거 CSV의 T02 하차는 당시 입력된 기록을 그대로 보여준다. 현재 R01→T01 정책과 다르다는 경고이지, 해당 과거 기록을 임의로 위조·오류 데이터로 확정하거나 삭제하는 처리가 아니다.

대시보드 상단에 메인 자료의 불일치 2건을 경고하고, 예약 목록의 `규칙 불일치` 필터 및 시스템 검증 탭에서 원본 하차·원본 상태·불일치 이유를 확인할 수 있다. 잘못된 신규 SQLite 조합도 같은 검증을 적용한다.

### 운영 집계 기준

- 규칙에 맞는 신규 SQLite 접수만 신규 운영 접수·대기 집계에 포함한다.
- 운영 배차 확정은 등록 운영 차량·운행편의 근거가 있는 배정만 포함한다. 실제 운행 개시·실시간 위치를 뜻하지 않는다.
- CSV 과거 예약·연구 등록부 예약·시험 운행편·과거 연구 배정은 별도 분류한다.
- 규칙 불일치는 운영 지표와 운행편 승객 합계에서 제외한다. 원본 상태는 바꾸지 않는다.
- 취소 기록은 활성 예약 합계에서 제외하지만 원본 검증 목록에서는 계속 조회할 수 있다.
- 실제 운행 차량 수는 관측 자료가 없어 `데이터 없음`으로 표시한다.

따라서 현 자료의 신규 운영 접수·대기·확정은 0이며, 과거 기록 5건은 그대로 목록에 남는다. 기존 기록을 지우거나 예약을 취소해서 0으로 만든 것이 아니다.

## 검증

지정 실행 모음 **32개 통과**, 최종 실행 33.407초. 기존 예약·순차 경유·합승·원본 보존 22개와 신규 UI·감사 10개다.

- 예약 생성·저장·재조회·취소·자동 노선/목적지·합승·정원·시간 중복의 기존 회귀 유지.
- CSV/SQLite의 잘못된 목적지와 승차 소속 탐지, 원본 상태·하차 값 유지, 취소된 불일치 기록 조회.
- 과거·시험·운영 기록의 지표 및 운행편 합계 분리.
- 임시 SQLite에만 운영 분류 스키마와 시험 배정 자료를 구성해 검증. 실제 차량을 생성하거나 운영 DB를 변경하지 않음.
- Streamlit AppTest의 5개 메뉴, 예약 목록·필터·재검토·취소, 원본 R02 등록부 이동, 모형 차량 표시 옵션.
- 이전 하위 메뉴 선택 복구, 자료 범위 전환 시 운행편 선택 초기화.
- 조회 연결이 실제로 `mode=ro`, `uri=True`인지 검증.
- 기존 데이터 98개, 정시성 등 보호 파일 30개, 기존 pyc의 해시 유지. 원본 변경·삭제 없음.
- `git diff --check` 통과. 자동 스테이징·커밋·푸시 없음.

실행:

```powershell
.\.venv\Scripts\python.exe -B scripts/verify_operations_ui.py
```

정시성 테스트·계산은 이번 실행 모음에서 제외했다. 기존 연구 결과를 대시보드의 별도 탭에 배치한 것 외에 정시성 관련 전용 파일과 처리 로직을 수정하지 않았다.

## 실제 브라우저 확인의 한계

computer-use의 browser access host가 연결되지 않아 이번 수정 화면을 실제 브라우저에서 확인하지 못했다. AppTest는 화면 구성과 동작을 검증하지만 최종 픽셀 배치·지도 타일·화면 폭별 스크롤을 보장하지 않는다. 실제 브라우저에서 좌우 컬럼 균형, 표 가로 스크롤, 모바일/좁은 창, 지도 아이콘과 레이어 토글을 추가 확인해야 한다.
