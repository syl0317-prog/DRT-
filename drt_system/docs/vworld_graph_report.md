# V-World 도로망 그래프 1차 구축 결과

## 범위와 실행

이번 단계는 원본 도로 형상의 끝점 기반 기하학적 후보 그래프 구축이다.
GITS 적용, DRT 경로 탐색, 앱 연계, 배차 로직 변경은 수행하지 않았다.

프로젝트 최상위 PowerShell에서 실행:

```powershell
.\venv\Scripts\python.exe -B drt_system/scripts/build_vworld_graph.py
.\venv\Scripts\python.exe -B -m unittest discover -s drt_system/tests -p test_vworld_graph.py -v
```

실행 스크립트는 현재 작업 디렉터리와 무관하게 기본 입력/출력 경로를 결정한다.
`--source`, `--output-root`로 대체 경로를 지정할 수 있다.
NetworkX, pyproj, Shapely를 사용하며 이번 작업에서 패키지를 설치하거나 의존성 파일을 수정하지 않았다.

## 생성 파일

- `drt_system/modules/vworld_graph.py`: 그래프 구축, 형상 진단, 교차 후보 검출, 결과 저장
- `drt_system/scripts/build_vworld_graph.py`: 명령행 실행점
- `drt_system/tests/test_vworld_graph.py`: 오프라인 테스트
- `drt_system/docs/vworld_graph_report.md`: 본 보고서

실제 산출물 폴더:

`drt_system/data/derived/20261111T075407044884Z_b514a0039e774405ab58d64252d92ad2/`

그 안에 다음 5개 파일을 생성했다.

| 파일 | 내용 |
|---|---|
| `vworld_graph.graphml` | 속성을 보존한 NetworkX MultiGraph |
| `vworld_nodes.geojson` | 노드 좌표, 차수, 연결 성분 ID |
| `vworld_edges.geojson` | 원본 형상, 링크 속성, 길이, 노드·성분 대응 |
| `connectivity_report.json` | 연결 성분별 엣지 목록·길이, 막다른 끝점, 형상 문제, 교차 후보 |
| `build_metadata.json` | 실행 ID·시각, 입력/구현 SHA-256, 라이브러리 버전, CRS 해석·구축 정책 |

UTC 마이크로초 시각과 UUID로 실행 ID를 생성하고, 실행 폴더는 `exist_ok=False`로 생성한다.
JSON 파일도 배타적 생성 모드로 저장한다. 재실행은 새 폴더를 만들며 기존 결과를 덮어쓰지 않는다.

## 구축 규칙과 해석

- LineString과 MultiLineString을 지원한다. 후자는 각 내부 선을 독립 엣지로 보존한다.
- 정확히 같은 XY 끝점만 후보 노드로 합친다. 근접점 스냅과 선 분할은 하지 않는다.
- 평행·중복 링크가 소실되지 않도록 MultiGraph를 사용한다. 엣지 키는 피처·파트 인덱스다.
- 모든 원본 속성은 JSON으로 보존한다. 링크 ID·도로명·도로등급·도로유형·최고속도·차량 제한은 별도 속성으로도 제공한다.
- `max_spd`는 원본 값이며 운영속도나 검증된 법정 제한속도로 새롭게 해석하지 않는다.
- 길이는 `pyproj.Geod(ellps='WGS84')`로 각 선분의 타원체 거리를 합산한다. Z는 길이 계산에 사용하지 않는다.
- 원본에 명시적인 CRS가 없어 좌표를 WGS84 경위도로 해석했다. 원본 CRS의 출처 확인은 남아 있다.
- 모든 엣지는 `direction=unknown`이다. 무방향 그래프는 연결성 진단용이며 양방향 운행 허용을 뜻하지 않는다.
- 그래프에 `topology_only=True`, `routing_permitted=False`를 기록한다. 이는 의미 표시이며 NetworkX의 탐색 함수를 기술적으로 차단하는 장치는 아니다.
- 끝점이 같은 경우도 실제 층위·통행 가능성은 미검증이다. 회전 제한과 진출입 제한도 검증하지 않았다.
- STRtree로 형상 교차를 검사하고 내부 교차·끝점/선 내부 접촉·중첩을 검토 후보로 보고한다. 자동 연결하지 않는다.
- 후보 검사는 정확한 기하학적 교차에 한정된다. 근접하지만 접촉하지 않는 T자 도로의 접속 가능성은 판정하지 않는다.

## 테스트와 검증

`unittest` 9개 테스트 모두 통과했다.

1. LineString·다중 파트 처리 및 성분·막다른 끝점
2. 적도 1도 WGS84 기준값(111,319.490793m)과 거리 비교 및 원본 속성 보존
3. 연속 중복 좌표·평행 링크 보존 및 방향 unknown
4. Z가 다른 교차선의 미연결 및 후보 기록
5. T자 접촉의 미분할 및 후보 기록
6. 근접 끝점의 임의 병합 방지
7. 빈 형상·0길이·좌표 범위 오류·NaN·미지원 형상 제외
8. 5종 파일 저장·GraphML 재읽기·고유 실행 ID·기존 결과 및 입력 불변
9. 실제 데이터의 사전 분석 수치 회귀 검증

실제 생성한 5개 산출물도 별도로 재읽었다. GraphML의 노드·엣지 수와 모든 방향 unknown,
GeoJSON의 노드·엣지 피처 개수를 확인했다.

## 기존 프로젝트 영향

요청한 4개 신규 소스/문서와 새 실행 폴더만 생성했다.
기존 app.py, route_engine.py, map_view.py, 스케줄러, sewook31 파일 및 원본 데이터는 수정하지 않았다.
기존 앱이 신규 모듈을 import하지 않으므로 실행 경로는 바뀌지 않는다.
기존 앱 테스트는 실행하지 않았으며, 신규 테스트가 기존 앱 전체의 정상 작동을 보증하지는 않는다.
Python은 `-B`로 실행하여 개인 폴더의 바이트코드 갱신을 피했다.
작업 시작 시 이미 있던 개인 폴더의 바이트코드 변경 및 미추적 파일은 그대로 유지했다.
네트워크/API 호출, 예약 데이터 접근, Git 업로드는 하지 않았다.
