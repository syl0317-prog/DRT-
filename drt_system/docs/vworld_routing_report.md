# V-World 독립 경로 탐색 3차 개발

## 생성 파일과 범위

- `drt_system/modules/vworld_router.py`: GraphML 읽기, 노드 스냅, 모드별 방향 그래프, 최단거리 탐색
- `drt_system/scripts/test_vworld_routing.py`: 실제 데이터 예제 실행 및 고유 폴더 저장
- `drt_system/tests/test_vworld_router.py`: 경로 탐색 테스트 12개
- `drt_system/docs/vworld_routing_report.md`: 본 보고서

기존 모듈·Streamlit·OSRM·스케줄러·sewook31·입력 데이터는 수정하지 않았다.
네트워크 호출 및 GITS 속도 사용은 없다. 1차 모듈의 WGS84 GEOD를 재사용한다.

## API와 실행

```python
from modules.vworld_router import VWorldRouter
router = VWorldRouter.from_graphml(graphml_path)
result = router.route((37.4783405, 127.1437479), (37.47, 127.15),
                      mode="experimental", max_snap_m=100)
```

입력은 `(위도, 경도)` 순서이고 출력 GeoJSON은 표준 `(경도, 위도)` 순서다.
mode 기본값은 verified다. 실패는 예외 대신 `success=False`와 구체적 reason으로 반환한다.
잘못된/존재하지 않는 GraphML 파일은 로딩 시 예외가 발생하며 입력 파일 오류를 숨기지 않는다.

```powershell
.\venv\Scripts\python.exe -B drt_system/scripts/test_vworld_routing.py
.\venv\Scripts\python.exe -B -m unittest discover -s drt_system/tests -p 'test_*.py' -v
```

실행기는 `--graph`, `--origin LAT LON`, `--destination LAT LON`, `--max-snap-m`을 지원한다.
GraphML을 지정하지 않으면 derived 폴더에서 경로명 순으로 마지막 그래프를 선택한다.
향후 그래프가 여러 개라면 재현성을 위해 `--graph`를 명시해야 한다.

## 스냅과 거리 해석

이번 구현은 가까운 노드에 연결한다. 모든 노드에 대해 WGS84 타원체 거리를 계산하고 가장 가까운 노드를 선택한다.
기본 최대 스냅 거리는 각 끝점당 100m다. 출발 또는 도착 스냅이 이를 초과하면 중단한다.
스냅은 모드 필터링 이전의 원본 그래프에서 수행한다. 가까운 노드가 검증망에서 단절되어도 먼 검증 노드로 자동 우회하지 않는다.

노드 스냅은 긴 링크 중간에서 접근할 때 접근 거리가 과장되거나, 같은 노드에 스냅되어 도로 거리가 0이 될 수 있다.
실제로 초기 예제 목적지 `(37.4775997, 127.1429823)`는 노드까지 122.42m라 기본 제한에서 거부되었다.
실행 결과는 별도 폴더 `20261111T083104199001Z_e6c4daa9874c42f2b39068b1bb66c52c`에 보존했다.

엣지 스냅은 도로 중간의 최근접점과 분할 구간을 사용하므로 노드 스냅의 과장 문제를 줄일 수 있다.
하지만 그 지점에 실제 진입할 수 있는지, 중앙분리대·고가도로·담장 등을 통과하지 않는지는 별도 검증이 필요하다.
이번에는 엣지 스냅을 구현하지 않았다. 후속 구현에서도 진입 근거가 없으면 실험 모드로 제한해야 한다.
필요하다면 미터 단위 투영 및 분할 구간의 타원체 길이 재계산, 같은 엣지 양 끝 스냅, 평행 차로 오접속 테스트가 필요하다.

`road_distance_m`는 선택된 도로 엣지 길이 합계다.
`connector_distance_m`는 입력점~스냅 노드 간 직선 거리 합계이며 실제 도보/차량 접근 거리로 검증되지 않았다.
둘을 합한 값은 이름에 straight_connectors를 포함하여 별도로 제공한다.
속도 시나리오는 도로 거리만 사용하며 접근 시간·신호·정차·회전·대기는 포함하지 않는다.

## 모드별 정책

### 검증 모드

unknown 방향은 모두 차단한다. 사용 가능한 방향 값은 형상 좌표 순서 기준 forward/reverse/both다.
direction_verified 및 direction_evidence, 양 끝 노드의 connectivity_verified 및 connectivity_evidence가 필요하다.
스냅 지점은 access_verified 및 access_evidence도 필요하다.
현재 그래프에는 이 근거가 없어 탐색을 차단한다. 코드가 근거 문자열의 진위를 독립 인증하는 것은 아니다.
향후 데이터 검증 절차에서 올바른 방향 및 접속·접근 증거를 공급해야 한다.
개별 회전 제한을 표현하지 않으므로 노드 connectivity_verified는 허용된 링크 간 접속이 모두 검증된 경우에만 사용해야 한다.
이 조건을 충족하지 않는 망은 향후 회전 제한을 표현하는 그래프 확장이 필요하다.

### 실험 모드

유효한 모든 원본 엣지를 양방향으로 가정한다. 결과와 GeoJSON, 모든 시간 시나리오에 experimental을 표시한다.
원본 그래프의 기하학적 접속을 사용하며 실제 주행 가능성은 확정하지 않는다.
171개 교차 후보 및 T자 접속 후보를 연결하거나 새 노드로 만들지 않는다.

## 최단거리와 형상

NetworkX MultiDiGraph에서 length_m을 가중치로 최단경로를 계산한다.
인접 노드 사이의 평행 엣지는 최저 길이를 선택하고 동률이면 엣지 키 문자열 순으로 선택한다.
최단경로 가중치와 결과에 사용되는 실제 엣지 선택 기준은 동일하다.
각 엣지를 진행 방향으로 뒤집어 연결하고 인접 중복 좌표만 제거한다.
원본 GraphML은 NetworkX 순회 순서가 원래 형상 방향과 다를 수 있으므로 형상 시작/끝과 노드 좌표를 대조한다.
일치하지 않는 형상 또는 잘못된 길이의 엣지는 제외한다.
경유 엣지 ID·링크 ID·도로명·길이를 순서대로 반환한다. 같은 노드에 스냅되면 거리는 0, 형상은 Point다.

## 테스트 결과

총 30개 통과: 기존 그래프 9개 + GITS 검증 9개 + 신규 경로 12개.
신규 검증 범위는 정상 경로, 단절, unknown 차단, 실험 역방향, 출발/도착 스냅 제한,
평행 엣지 선택, 링크 ID/도로명 보존, 중복 좌표, GeoJSON 방향, 3종 속도 시나리오,
검증 근거에 따른 단방향 및 접근 차단, 교차점 미연결, 잘못된 입력/빈 그래프,
동일 스냅 노드, 실제 GraphML 로딩·탐색이다.
기존 앱의 UI 회귀 테스트는 실행하지 않았다. 신규 모듈은 앱에 연결하지 않았다.

## OSRM 비교를 위한 후속 과제

동일 출발·도착·경유 순서와 좌표계, 스냅/접근 거리 기준을 맞추는 비교 어댑터가 필요하다.
OSRM 결과의 캐시 시각·모델 출처와 V-World의 기하학적 가정·속도 시나리오를 분리해 표시해야 한다.
거리 차이와 형상 겹침·우회 정도를 비교할 수 있으나 실험 거리·시간을 실제 운행 정확도로 해석하면 안 된다.
방향·회전·진출입·입체교차 검증, 엣지 접근 근거, 망 커버리지 차이를 먼저 조사해야 한다.
OSRM의 예측 시간과 가정 속도 시간을 동일 종류의 추정값으로 취급하지 않는다.
이번 단계에서는 비교 어댑터, Streamlit 통합, DRT 탐색 최적화 및 배차 변경을 구현하지 않았다.
