# 연구용 정시성 및 트램 환승 분석

## 실행

프로젝트 최상위 PowerShell에서 다음 명령으로 기존 사이트를 실행한 뒤 **정시·환승 분석 → 개별 운행 분석**을 선택한다. 기존 정시성 검증은 같은 메뉴의 **기존 정시성 검증**에서 접근한다.

```powershell
python -B -m streamlit run drt_system/app.py
python -B -m unittest discover -s drt_system/tests -p test_punctuality_simulation.py -v
```

기존 환경의 Streamlit, Altair, pandas, NumPy, requests를 사용한다. SciPy나 추가 패키지를 설치하지 않는다. 기존 정시성 검증 메뉴도 그대로 유지한다.

## 확인한 기존 데이터와 재사용 범위

- `drt_system/data/reservations.csv`: 예약 6행. 실제 필드는 reservation_id, created_at, vehicle_id, boarding_stop, tram_stop, tram_departure, passengers, status이다. DRT 출발시각·목표 도착시각·실제 도착시각은 없다. `tram_departure`는 날짜가 없는 시각이며 이 필드를 실제 시간표로 해석하지 않는다. 새 화면은 예약을 읽거나 변경하지 않는다.
- `modules.settings.stops_path()`로 설정된 `drt_system/data/drt_stops.csv`를 읽는다. 6개 정류장의 ID·이름·유형·위경도를 재사용한다. 후보 좌표의 실제 환승 보행 경로가 검증된 것은 아니다.
- `modules.route_engine.calculate_road_route()`는 OSRM 캐시 함수의 재노출이다. 기존 방향성 캐시 11개를 `allow_network=False`로 조회하여 `duration_min`, `retrieved_at`을 재사용한다. 캐시 미스일 때 사용자가 온라인 조회를 허용하면 별도 읽기 전용 HTTP 요청으로 이동시간만 받아 기존 캐시에 쓰지 않는다.
- `calculate_reservation_pickup()`은 예약 정류장 사이 경로와 역산 탑승시각, `calculate_integrated_schedule()`은 선택된 방문 순서의 경로·정차·혼잡계수와 배차시각을 계산한다. 이들은 실제 차량 위치·지연 기반 ETA가 아니며, 새 모형은 해당 운영 함수를 호출하지 않는다. 새 화면은 선택한 정류장 간 가상 운행 1건을 분석한다.
- `data/assumptions/tram_timetable.json`은 배차간격 10/15분의 가정 자료이며 실제 출발 시간표가 아니다. 새 화면의 트램 출발 날짜·시각은 모두 사용자 지정 가상 시간표다.
- 기존 `punctuality_sim.py`는 삼각분포 기반의 별도 정시성 검증 모형이다. 기존 모형·설정·결과 파일을 변경하거나 혼합하지 않는다.
- GITS 검증 완료 링크는 0개다. GITS 속도나 V-World 형상을 이번 시간 계산에 사용하지 않는다.

## 입력과 계산

한국시간 날짜와 시각을 결합한다. 목표·트램 시각이 익일이면 출발일 이후 일수를 1로 지정한다. 자동으로 날짜를 추측하지 않으며, 출발 이전 목표/트램 시각은 오류로 표시한다. 결과에 날짜를 포함한다.

기준 이동시간은 OSRM 모형 또는 사용자 직접 입력 중 하나이며 화면·다운로드 자료에 출처를 명시한다. OSRM 실패 시 오류를 표시하고 직접 입력으로 전환해야 한다. 임의의 시간으로 자동 대체하지 않는다.

```text
혼잡 반영 이동시간 = 기준 이동시간 × (1 + 증가율/100)
예상 도착 = 출발 + 혼잡 반영 이동시간
지연 반영 도착 = 예상 도착 + 추가 지연
정시 = 지연 반영 도착 <= 목표 도착 + 정시 허용 오차
탑승 준비 완료 = 지연 반영 도착 + 보행시간 + 추가 환승 여유
환승 성공 = 탑승 준비 완료 <= 가상 트램 출발
환승 실패 확률 = 실패 횟수 / 반복 횟수 × 100
```

목표 대비 여유는 목표 도착 − 지연 반영 도착이다. 환승 잔여는 트램 출발 − 준비 완료이며, 음수일 때 실패 초과시간은 그 절댓값이다. 목표시간과 같거나 트램 출발시각에 정확히 준비되면 성공으로 판정한다.

## 연구용 기본 가정

| 항목 | 기본값 |
|---|---|
| 반복/시드 | 1,000회 / 20261113 |
| A/B/C 증가율 | 0% / 20% / 50% |
| 상세 시나리오 | A |
| 지연 분포 | 균등분포 0~10분 |
| 단일 계산/고정분포 지연 | 5분 |
| 절단 정규분포 | 절단 전 평균 5분, 표준편차 2분, 0~10분 범위 |
| 보행/추가 환승 여유 | 3분 / 2분 |
| 정시 허용 오차 | 0분 |
| 수동 기준 이동시간 | 15분 |
| 가상 출발/목표/트램 시각 | 08:00 / 08:25 / 08:30 |

이 값들은 실제 위례 운행 특성을 나타내지 않는다. 세 시나리오에 같은 난수 지연 표본을 사용해 이동시간 증가 가정의 효과를 비교한다. C 증가율은 B보다 커야 한다. 모든 지연은 0 이상이다. 절단 정규는 누적분포 역함수로 표본을 생성하며, 정규 표본을 단순히 경계값으로 잘라내는 분포가 아니다. 입력 평균·표준편차는 절단 전 값이다. 확률질량이 수치적으로 너무 작은 극단적인 절단 구간은 오류로 처리한다.

평균 총 소요시간은 혼잡 반영 이동시간과 표본 지연 합계의 평균이다. 기준 대비 평균 도착 지연은 혼잡 증가분과 표본 지연의 합이다. 목표 대비 평균 초과는 목표보다 늦는 양수 부분의 평균이며 조기 도착은 0으로 센다.

## 화면과 모듈

- `punctuality_simulation.py`: I/O 없는 단일 정시·환승 계산, 세 분포 표본 생성, A/B/C 몬테카를로 비교. 추후 검증된 관측 잔차를 지연 표본으로 제공하는 모델로 확장할 수 있다.
- `punctuality_inputs.py`: 설정된 정류장 목록, 읽기 전용 OSRM 캐시/온라인 조회, 명시적인 수동 입력. 기존 경로 모듈은 변경하지 않는다.
- `punctuality_views.py`: 사용자 입력, 핵심 지표, 날짜 포함 시간 흐름, 시나리오별 정시율/환승 실패 그래프, 표본 지연 히스토그램, 분석표, 출처·가정 JSON 및 요약 CSV 다운로드.
- `app.py`: 새 메뉴 문자열과 해당 분기 호출만 추가한다. 기존 메뉴/기능은 유지한다.

입력을 변경하면 이전 결과를 숨기고 다시 실행하도록 하여 오래된 결과가 새 조건의 결과처럼 남지 않게 한다. 결과는 자동 저장하거나 예약·배차·운행시간에 반영하지 않는다.

## 검증과 한계

새 기능 테스트는 정시·환승 등호 경계, 허용 오차, 자정 처리, 세 분포, 음수/결측·무한대 입력 거부, 시드 재현성, 확률 범위와 합계, A/B/C 비교, 실제 캐시 읽기, 모의 OSRM 성공·실패, 수동 전환을 포함한다. Streamlit AppTest로 실제 app.py의 메뉴 진입과 캐시/수동 계산, 절단 정규분포 및 익일 입력, 지표/표/차트 생성, 입력 변경 시 결과 초기화를 검사한다.

AppTest는 브라우저 픽셀 렌더링 검증이 아니다. 브라우저 시각 검토·외부 OSRM 서버 실연결은 미검증이다. 기존 예약·배차 UI의 모든 업무 시나리오를 다시 실행한 것은 아니며, 기존 파일 해시 보존과 기존 테스트의 통과를 별도로 기록한다.

실제 자료 확보 후에는 계획/실제 출발·도착·트램 탑승 시각, 차량·경로·정차·합승·시간대, GPS 매칭, 보행시간, 실제 트램 시간표를 출처와 함께 확보해야 한다. 검증용 기간을 분리해 잔차 분포를 추정하고, 예측률의 보정·표본 수·불확실성을 평가해야 한다. 차량별 실시간 ETA와 운영 배차 적용은 별도 단계다.
