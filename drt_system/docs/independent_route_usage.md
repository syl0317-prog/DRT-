# R02 신규 독립 연구용 노선

예약 통합 업데이트: 현재 **예약 관리**는 노선 선택 없이 8개 정류장을 사용하는 통합 화면이다. 기존/신규 예약·취소 방식은 `unified_reservations_usage.md`를 따른다. 아래 분리 예약 경로와 0/4개 초기 상태는 최초 구현 당시 기록이다. 이번 통합 작업 시 실제 등록부에는 V05~V08 네 위치가 저장되어 있음을 확인했으며 이를 변경하지 않았다.

## 현재 등록 상태

기존 정류장은 `drt_system/data/drt_stops.csv`의 T01/T02 및 D01~D04이다. 기존 지도·배차는 선택한 경유지·방문 순서를 계산하는 기능이며 영구 고정 노선 등록부가 없었다. OSRM 캐시나 GITS의 route_id는 저장된 운영 노선 ID로 간주하지 않는다. 기존 예약에는 노선 ID와 운행일자가 없다.

별도 등록부에 `R02 / 위례 DRT 신규 노선` 초안 1개를 생성했다. 위치는 제공되지 않았으므로 실제 가상정류장은 0/4개, 경로는 미계산, 활성화는 꺼져 있다. 테스트용 4개 좌표는 임시 DB에서만 사용했다. 기존 노선에 R01을 부여하거나 기존 예약을 R02로 이동하지 않았다.

## 사용 순서

```powershell
python -B -m streamlit run drt_system/app.py
```

1. **배차·경로 → 신규 독립 노선**에서 R02를 확인한다. 기존 지도·노선 설정과 배차·픽업 계산은 그대로 유지된다.
2. 새 이름과 위도·경도를 직접 입력하거나 별도 지도에서 클릭한다. 클릭만으로는 저장되지 않는다. 좌표·도로 접근 거리 검토 버튼을 사용할 수 있다.
3. ID·이름·좌표·순서를 확인하고 확인란을 선택한 뒤 정류장 저장을 누른다. 기본 제안은 V05~V08이며 기존/신규 정류장과 충돌하면 사용 가능한 다음 ID를 제안한다. 임의의 초기 좌표는 채우지 않는다.
4. 정확히 4개를 등록한다. 등록된 정류장을 선택해 이름·좌표·상태를 수정할 수 있다. ID 변경은 지원하지 않는다. 방문 순서 변경은 별도 4개 순서 선택에서 진행한다.
5. 4개 방문 순서, 선택적인 기존 트램 종점 T01/T02, 별도 연구용 차량을 설정한다. 차량은 `R02-V01`처럼 노선 접두사를 가진 ID를 사용한다. 쉼표로 여러 차량을 입력할 수 있고 정원을 명시한다. 실제 확보된 차량이라는 의미는 아니다.
6. OSRM 구간 경로 계산을 실행한다. 기본은 기존 방향성 캐시 읽기이며, 온라인 조회가 필요하면 명시적으로 허용한다. 원래 OSRM 캐시에는 쓰지 않는다.
7. 모든 구간이 성공하면 거리·시간·구간 표·초록 경로를 확인하고 연구용 노선을 활성화한다. 정류장 4개·순서·차량 설정·경로 성공이 모두 필요하다.
8. **예약 관리 → 신규 독립 노선 예약**에서 활성 노선·해당 노선의 탑승/도착 정류장·별도 차량·운행일자·첫 정류장 출발시각·정원·정차 가정을 입력한다. 기존 예약은 기본 선택인 **기존 예약 (노선 미지정)**에서 그대로 사용한다.
9. 신규 예약 내역과 별도 예정 일정을 확인하거나 신규 예약만 취소한다. 통합 대시보드에서 기존/신규 예약이 분리되어 집계되는지 확인한다.

## 위치·방문 순서 검증

- 영문자 시작 ID 형식을 검증하고 기존 정류장 ID와 신규 정류장 ID를 대소문자 구분 없이 비교한다.
- 위경도는 유한한 숫자와 전세계 위경도 범위를 확인한다. 기존 또는 신규 정류장에서 1m 미만인 위치는 중복으로 거부한다.
- 현재 분석 영역은 V-World 도로망 파일의 외접 범위이다. 위례의 공식 행정/사업 경계로 주장하지 않는다. 기존 창곡동 경계는 위례 전체가 아니므로 전체 신규 노선을 창곡동 내부로 제한하지 않는다. 실제 서비스 권역이 확정되면 해당 폴리곤 검증으로 확장해야 한다.
- WGS84 경위도 가정의 원본 도로를 EPSG:32652로 투영하고 가장 가까운 도로 형상까지의 거리를 미터로 계산한다. 원본 SHA-256과 검토 시각을 함께 저장한다.
- 도로 접근 거리는 안전한 승하차·정차 허용·차량 진입 가능의 증거가 아니다. `검토 완료`는 사용자의 검토 기록이며 운행 허가/안전 인증을 뜻하지 않는다.
- 방문 순서는 정확히 4개 ID를 중복 없이 포함한다. 선택적인 기존 트램 거점은 네 가상정류장 뒤의 종점이다. 사용자가 지정한 순서이며 최적 경로라고 표시하지 않는다.

## 저장 구조와 충돌 처리

```text
data/derived/drt_routes/
  routes.sqlite3                  # 유일한 정본: 노선·정류장·구간·신규 예약
  exports/<UTC시각_UUID>/
    routes.json                   # 동일 버전의 전체 스냅샷
    virtual_stops.csv
    route_segments.csv
    reservations.csv
```

SQLite의 단일 registry 상태에는 routes/stops/segments/bookings 및 버전이 들어 있다. `BEGIN IMMEDIATE`와 기대 버전 검사로 로컬 동시 수정·예약의 손실을 막는다. 화면을 연 버전도 유지하며, 다른 변경이 확인되면 입력 초기화/재조회 전에는 저장을 진행하지 않는다. 연결은 명시적으로 닫는다. 잠금·파일 쓰기 실패는 화면 오류로 안내한다.

내보내기는 버튼을 누를 때마다 새 폴더에만 생성한다. 내보내기 CSV/JSON을 편집해도 정본에는 반영되지 않는다. 내보내기 실패 시에도 정본의 트랜잭션과 기존 원본은 유지된다. 최초 R02 초안의 빈 정류장/예약 스냅샷도 별도 exports 폴더에 생성했다.

이 잠금은 같은 파일을 사용하는 로컬 프로세스에 대한 것이다. OneDrive에서 여러 PC가 동기화하는 SQLite 복제본 사이의 분산 잠금은 아니다. 다중 PC 운영은 중앙 DB/API로 전환해야 한다.

## 경로와 지도

기존 `route_engine.calculate_road_route()`를 `allow_network=False`로 재사용한다. 캐시 미스 및 온라인 허용 때만 기존과 같은 OSRM driving endpoint를 읽기 전용으로 조회한다. 기존 원본 캐시에 쓰지 않는다.

각 연속 정류장 쌍의 거리·시간·형상·출처·조회 시각을 저장한다. 전체 거리·시간은 해당 구간의 합이다. 한 구간이라도 실패하면 전체 상태를 failed로 저장하고 경로/거리/시간을 지운다. 직선을 실제 운행 경로로 대체하지 않는다. 각 구간 형상을 따로 그려 불연속 스냅 지점을 임의로 이어 그리지 않는다.

신규 후보·경로는 초록, 기존 정류장과 현재 세션의 기존 임시 경로는 파랑, 트램 거점은 별도 표시한다. 팝업에 이름·ID·소속 노선·방문 순서를 표시한다. 전체 보기에서 기존 임시 경로는 이전 기존 지도 화면에서 성공한 계산이 있을 때만 표시하며 영구 저장 노선으로 세지 않는다.

지도 클릭 컴포넌트와 세션 키를 기존 selected_lat/selected_lon과 분리했다. 기존 OSM/OSM Deutschland 제공자 선택은 유지한다. 대시보드는 읽기 전용으로 신규 후보와 저장 경로만 표시하고 OSRM을 자동 실행하지 않는다.

## 예약·배차 호환성 및 제한

기존 reservation_manager/integrated_scheduler/pickup_scheduler/shared_route는 원본 정류장 CSV와 기존 예약 스키마를 사용한다. 해당 알고리즘에 가상정류장을 섞으면 원본 스키마·방문 순서·차량 분리의 큰 변경이 필요하므로 그 부분은 변경하지 않았다.

신규 예약은 독립 등록부에 route_id·별도 차량 ID·날짜 포함 출발시각·탑승/도착 ID·승객 수·생성 시각·당시 노선과 구간 스냅샷을 저장한다. 기존 예약은 그대로 읽으며 신규 노선에 자동 배정하지 않는다. 동일 운행편은 좌석을 전 구간에 보수적으로 예약하며 구간별 좌석 재사용 최적화는 하지 않는다. 정원 초과와 같은 신규 차량의 다른 예정 운행편 시간 중복을 거부한다. 날짜는 UTC로 정규화하여 저장한다.

별도 예정 일정은 저장 OSRM 구간에 입력한 정류장 정차 가정을 더한 순차 일정이다. 승객의 실제 탑승·목적지 도착 가정 시각과 추가 여유 반영시각을 표시한다. 원래 트램 역산 배차 엔진의 결과가 아니며 가상 시간표의 환승 성공률을 이 모듈에서 새로 계산하지 않는다. 재배차·공차 이동·차고지·실시간 위치·지연 및 실제 차량 가용성 검증은 구현 범위가 아니다.

유효한 신규 예약이 있으면 정류장·순서·차량·경로를 변경하지 못하게 한다. 취소 후 변경할 수 있다. 구조가 바뀌면 기존 계산을 무효화하고 비활성화하여 다시 계산해야 한다. 운행 종료 시각은 예약 당시 OSRM 합계와 정차 가정으로 계산한 예정값이며 실측이 아니다.

## 대시보드

상단 예약/승객/배정 차량 지표는 기존 저장소 기준이라고 명시한다. 별도 노선 영역에는 등록된 신규 노선 수, 정류장 수, 활성 상태, 신규 유효 예약/승객 수, 계산된 거리·시간을 표시한다. 기존 방식의 정류장·예약도 노선 미지정으로 따로 안내한다. 실제 값이 없으면 미계산/등록 대기로 표시하며 중복 합산하지 않는다.

## 실행 검증과 향후 자료

최종 전체 자동 테스트 75개(신규 독립 노선 테스트 16개)가 통과했다. Streamlit 서버를 127.0.0.1:8513에서 일시 기동해 health와 루트 HTTP 200을 확인한 뒤 종료했다. 기존 데이터 파일은 변경되지 않았으며 상세 검증·변경 파일 목록은 `independent_route_validation.json`에 기록했다.

테스트용 위치는 임시 DB에서만 등록한다. 실제 R02에는 임의 좌표를 등록하지 않았다. 자동 테스트와 실제 브라우저 검증은 별개이며 브라우저 도구는 `The browser access host is unavailable` 상태였다. 실제 브라우저의 신규 지도 클릭·팝업·초록 경로·배경지도 및 제공자 전환은 사용자가 확인해야 한다.

실운행 검토에는 확정 서비스 권역, 실제 정류장 위치·보행 접근·승하차 공간·도로 방향/접근 제한, 정차 허용과 현장 안전 검토, 확보 차량·차고지·공차시간·근무표, 실제 트램 시간표와 보행시간, 실제 수요·운행기록이 필요하다. 기존 배차 엔진까지 일원화하려면 route_id를 받는 정류장/예약 저장소 인터페이스를 별도 설계·승인하는 것이 다음 단계다.
