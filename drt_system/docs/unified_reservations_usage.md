# 위례 DRT 통합 예약

## 사용법

```powershell
python -B -m streamlit run drt_system/app.py
```

기존 6개 메뉴를 유지한다. **예약 관리**에서 노선/저장소 선택 없이 탑승·하차 정류장, 희망 날짜·시간, 인원을 입력한다. 기본 탑승/하차 목록은 현재 저장된 D01~D04와 V05~V08의 8개 DRT 정류장이다. 이름과 좌표는 원본 정류장 CSV 및 R02 등록부에서 읽으며 임의 생성하지 않는다. R02가 비활성이어도 후보 정류장을 선택해 검토 요청을 접수할 수 있다.

`트램 환승 거점도 하차 목록에 표시`를 선택하면 기존 T01/T02가 하차 목록에 추가된다. 이 경우 가상 트램 출발 목표 날짜·시각을 선택적으로 기록할 수 있다. 실제 시간표로 표시하지 않는다. 탑승·하차 동일 ID, 잘못된 날짜/시간, 과거 희망시각, 정원 초과를 거부한다.

동일 입력으로 신청 버튼을 다시 누르면 같은 요청 키를 재사용해 중복 저장하지 않는다. 별도 요청을 의도한 경우 `동일 조건으로 별도 추가 요청 준비` 후 신청한다. 검토 요청이 차량 배정으로 자동 승격되지는 않는다. 조건을 바꿔 재신청할 때는 기존 검토 요청의 취소 여부도 확인한다.

## 실제 자료 확인

작업 시작 시 기존 CSV에는 6개 예약이 있고, R02 등록부에는 V05~V08의 이름·좌표와 계산된 경로가 저장되어 있었다. R02는 비활성이고 차량이 지정되지 않았으며 기존 R02 예약은 0건이었다. 이 상태나 저장 경로를 임의 변경하지 않았다.

현재 실제 화면은 8개 정류장을 표시하지만 R02의 자동 운행편 배정은 활성화와 별도 차량 지정 이후에만 가능하다. 원본에 없는 좌표나 정류장명은 채우지 않는다. 일부가 미등록이면 실제 개수를 알리고 없는 정류장을 생성하지 않는다.

## 세 저장소를 통합하는 방법

| 원본 | 실제 데이터 구조 | 조회·취소 |
|---|---|---|
| 기존 `drt_system/data/reservations.csv` | reservation_id, created_at, vehicle_id, boarding_stop, tram_stop, tram_departure, passengers, status | 원본을 읽고 별도 취소 기록을 적용한다. CSV 자체는 덮어쓰지 않는다. |
| R02 `data/derived/drt_routes/routes.sqlite3` | registry JSON의 bookings, 날짜 포함 운행편 출발, route_snapshot, segments_snapshot | 원본을 그대로 조회한다. 기존 R02 예약 취소는 이 원본 SQLite의 해당 booking만 변경하고 revision을 증가시킨다. |
| 신규 `data/derived/unified_reservations/reservations.sqlite3` | requests 및 csv_cancellations | 새 통합 요청의 정본. 희망시각, 정류장 스냅샷, 내부 경로·배차 판정·근거를 보관한다. |

기존 데이터 마이그레이션이나 원본 스키마 변경은 없다. 기존 요청을 통합 DB에 복사하지 않고 연합 조회하므로 이중 집계를 피한다. 예약 번호는 `CSV:<저장소범위>:<원본ID>:<행지문>`, `R02:<저장소범위>:<원본ID>`, `UNI:<UUID>`로 구분한다.

기존 CSV의 `created_at`은 생성시각이며 희망 탑승일자가 아니다. `tram_departure`는 가상 트램 시각이며 희망 탑승시각이 아니다. 과거 CSV의 탑승 날짜/시간은 `미기록`으로 표시한다. 과거 R02 예약은 저장 운행편과 구간에서 예정 탑승시각을 산출하고, 사용자 희망시각 원문과 구분한다. 새 요청만 희망 날짜·시간을 원문으로 기록한다. 저장은 UTC, 화면은 한국시간으로 표시한다.

### CSV 취소와 원본 보존 조건

CSV 원본에 취소를 직접 기록하는 것은 원본 덮어쓰기 금지 조건과 충돌한다. 따라서 취소 사실은 원본 파일 경로·행 지문으로 식별한 `csv_cancellations`에 저장하고, 기존 `reservation_manager.load_reservations()`가 취소 상태를 적용하도록 읽기 경계만 연결했다. 기존 좌석 계산, 합승 엔진, 관리자 조회도 이 함수를 사용하므로 취소된 좌석이 해제된다.

원본 CSV를 직접 읽는 외부 도구에는 취소 상태가 반영되지 않는다. 통합 서비스 또는 기존 호환 조회 함수를 사용해야 한다. 원본 파일을 직접 마이그레이션하는 작업은 수행하지 않았다.

## 내부 배차 판단

- 기존 DRT 간, 기존↔R02, R02 역방향, 미지원 트램 연결은 요청을 접수하되 `배차 검토 필요`로 저장한다. 날짜와 희망 탑승시각을 받는 통합 배차 엔진이 기존 엔진에 없으므로 임의로 차량을 배정하지 않는다.
- R02의 저장된 순방향 구간이며 활성화·별도 차량·정원이 확보된 경우에만 독립 연구용 운행편을 배정한다. 선택한 탑승 정류장 앞의 주행·정차 시간을 역산해 첫 정류장 출발을 결정하므로 중간 정류장의 희망 탑승시각을 전체 노선 출발로 오해하지 않는다.
- 시작 시각이 이미 지난 것으로 역산되거나 정원/차량 운행편이 충돌하면 검토 상태로 남긴다. 기존 CSV에 같은 차량의 날짜 미기록 예약이 있으면 가용성을 추정하지 않는다.
- R02 원본 예약과 통합 요청의 확정 연구용 운행편을 합쳐 정원·시간 중복을 확인한다. 기존 R02 예약 API도 통합 요청이 점유한 좌석을 확인한다. 정원을 전 구간에 보수적으로 적용하며 구간별 좌석 재사용 최적화는 하지 않는다.
- 지원 운행편도 `실제 운행 확정`이 아니다. 실제 수요·차량 실시간 상태·공차 이동·근무표·승하차 안전·운행허가는 확인하지 않았다.
- 경로 확인은 기존 방향성 OSRM 캐시 또는 명시적으로 허용한 온라인 조회를 사용한다. OSRM이 NoRoute라고 응답하면 접수하지 않는다. 연결 실패나 캐시 미스는 경로 미확인 사유를 붙여 검토 접수한다. 자동 배차로 처리하지 않으며 직선으로 대체하지 않는다. 기존 캐시는 덮어쓰지 않는다.

새 예약 생성은 통합 DB 트랜잭션 중 R02 DB도 잠그고 최신 상태를 재확인한다. 요청 키에 UNIQUE 제약을 두고, 잠금 이후 정원/운행편을 확인하여 중복 생성과 좌석 초과를 방지한다. 로컬 공유 파일의 동시 접근에 대한 처리이며, 여러 PC에서 OneDrive 복제본을 동기화하는 분산 DB 보장은 아니다.

## 취소와 다른 메뉴

통합 목록에서 예약을 선택하면 출처에 따라 정확한 취소 경로로 처리한다. 통합 예약은 통합 DB, 기존 R02 예약은 기존 R02 DB, 기존 CSV 예약은 원본 보존용 취소 로그로 처리한다. 취소는 재실행 후에도 유지되고, 좌석 판정은 취소된 요청을 제외한다.

대시보드는 세 저장소의 유효 접수를 중복 없이 합산한다. `배차 검토 필요`도 유효 접수에 포함하지만 건수를 별도로 알리며 배차 완료 실적이라고 표시하지 않는다. 실제 저장 요청과 연구용 정시성 결과는 계속 분리한다.

배차·경로의 기존 파란 경로와 R02 초록 경로·정류장·등록부는 변경하지 않는다. 기존 합승 시뮬레이션은 호환되는 기존 CSV 예약만 사용하고, R02 지원 예약은 별도 저장 구간 기반 예정 일정으로 조회한다. 지원하지 않는 통합 요청은 제외 사유를 표시한다. 정시성 입력과 차량 수·정원 설정은 유지한다.

## 변경 파일

- 신규: `modules/unified_reservations.py`, `modules/unified_reservation_views.py`, `tests/test_unified_reservations.py`.
- 수정: `app.py`, `dashboard_views.py`, `reservation_manager.py`의 취소 적용 읽기 경계, `independent_routes.py`의 공유 좌석/유효 예약 확인, `independent_route_views.py`의 집계.
- 기존 테스트의 예약 화면 접근 경로를 통합 UI에 맞게 갱신했다. 원래 예약 알고리즘 자체의 생성·좌석·취소 검증도 임시 CSV에서 유지한다.

전체 검증 결과 및 원본 해시 확인은 `unified_reservations_validation.json`에 기록한다. 실제 브라우저 시각 검증과 외부 OSRM 서버 실연결은 자동 테스트와 구분한다.

최종 전체 테스트 89개(신규 통합 예약 테스트 14개)가 통과했다. 기존 데이터 77개 파일의 해시는 변경되지 않았으며 기존 CSV와 R02 등록부도 동일하다. 실제 통합 저장소의 신규 요청은 0건이다. 임시 CSV·SQLite에서만 테스트 예약을 생성·취소했다. Streamlit 서버의 루트·health HTTP 200을 확인한 후 종료했다. 브라우저 도구는 `The browser access host is unavailable` 상태로 실제 화면은 미검증이다.
